# Part 9. 운영과 보안

## 90. 자격증명과 보안

자동화에는 API 키와 비밀번호가 들어가므로, 보안은 선택이 아니라 필수입니다. n8n의 보안은 자격증명 관리에서 시작됩니다.

자격증명(Credentials)은 n8n이 API 키 같은 비밀값을 따로 보관하는 기능입니다. 노드 설정에 직접 키를 적는 대신 자격증명을 연결합니다. 화면에서는 마스킹되어 보이고, 워크플로우를 내보내도 키는 포함되지 않습니다. 팀으로 쓸 때는 자격증명에 접근할 수 있는 사람을 제한할 수 있습니다.

셀프호스팅 보안의 기본을 정리합니다. 첫째, 관리자 비밀번호를 강하게 정합니다. 기본값 그대로 두지 않습니다. 둘째, HTTPS를 적용합니다. 특히 웹훅을 외부에 공개한다면 필수입니다. 셋째, n8n을 최신 버전으로 유지합니다. 보안 패치가 포함된 업데이트가 자주 나옵니다. 넷째, 방화벽으로 접근을 제한합니다. 에디터 화면은 내부망이나 VPN에서만 열리게 하는 것이 안전합니다.

AI 기능을 쓸 때의 보안도 생각합니다. 프롬프트에 개인정보를 그대로 넣지 않습니다. 꼭 필요하면 마스킹하거나 최소한으로 줄입니다. 에이전트에게 주는 도구는 최소 권한으로 만듭니다. 읽기만 하면 되는 도구에 쓰기 권한을 주지 않습니다. 외부로 나가는 데이터가 있다면, 어디로 무엇이 나가는지 목록으로 관리합니다.

워크플로우를 공유할 때는 내보내기 파일에 자격증명이 포함되지 않는지 확인합니다. n8n의 내보내기는 기본적으로 자격증명을 제외하지만, 노드 설정에 키를 직접 적어 두었다면 그대로 노출됩니다. 공유 전에는 텍스트 검색으로 키 패턴이 있는지 확인하는 습관을 들이세요.

핵심 정리
- 비밀값은 반드시 자격증명으로 관리하고 노드에 직접 적지 않는다.
- HTTPS, 강한 비밀번호, 최신 버전 유지가 기본이다.
- AI 프롬프트의 개인정보는 최소로, 도구 권한도 최소로 한다.
