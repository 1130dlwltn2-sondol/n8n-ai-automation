# Part 2. 워크플로우 기초

## 20. 트리거와 노드

워크플로우는 항상 트리거 노드에서 시작됩니다. 트리거는 워크플로우를 깨우는 조건입니다. n8n의 대표 트리거는 다음과 같습니다.

Manual Trigger는 사람이 직접 실행 버튼을 누를 때 시작됩니다. 테스트와 디버깅용입니다. Schedule Trigger는 정해진 시간에 시작됩니다. cron 표현식으로 "매일 아침 9시" 같은 일정을 지정할 수 있습니다. Webhook Trigger는 외부에서 HTTP 요청이 오면 시작됩니다. n8n이 URL을 하나 만들어 주는데, 그 주소로 POST 요청을 보내면 워크플로우가 실행됩니다. 앱 트리거는 Gmail, Slack, GitHub 같은 외부 서비스에서 이벤트가 발생하면 시작됩니다. 예를 들어 "새 이메일이 오면" 같은 조건입니다.

트리거 다음에는 일반 노드가 옵니다. 노드는 크게 액션 노드와 로직 노드로 나뉩니다. 액션 노드는 외부에 뭔가 합니다. 메시지 보내기, 파일 읽기, AI에게 질문하기가 여기에 속합니다. 로직 노드는 흐름을 제어합니다. 조건에 따라 갈라지거나(IF), 여러 갈래를 합치거나(Merge), 반복하거나(Loop) 합니다.

노드를 연결할 때는 순서가 중요합니다. 데이터는 왼쪽에서 오른쪽으로 흐릅니다. 앞 노드의 출력이 뒤 노드의 입력이 됩니다. 노드를 클릭하면 그 노드가 받은 입력과 내보낸 출력을 볼 수 있어, 흐름이 막혔을 때 어디서 문제가 생겼는지 추적하기 쉽습니다.

노드 설정 화면의 오른쪽 위에는 노드 실행 결과가 표시되고, 설정이 바뀌면 다시 실행해서 바로 확인할 수 있습니다. 이런 식으로 한 노드씩 검증하면서 만들어 가는 것이 n8n 작업의 기본 리듬입니다.

핵심 정리
- 워크플로우는 반드시 트리거 노드에서 시작한다.
- Manual, Schedule, Webhook, 앱 트리거가 대표적이다.
- 액션 노드는 작업을, 로직 노드는 흐름 제어를 담당한다.
- 노드마다 입출력을 확인하며 한 단계씩 검증한다.
