# 91. 모니터링과 백업

자동화는 만들고 끝이 아니라 운영하는 것입니다. 사람이 안 보고 도는 만큼, 상태를 들여다보는 장치가 필요합니다.

실행 이력(Executions)은 가장 기본적인 모니터링입니다. 성공과 실패가 시간 순으로 쌓이고, 실패한 건은 클릭해서 어디서 멈췄는지 볼 수 있습니다. 중요한 워크플로우는 주기적으로 이력을 확인하는 습관을 들입니다. 실패율이 갑자기 오르면 외부 API 변경이나 데이터 형식 변경을 의심합니다.

알림은 Error Workflow로 자동화합니다. Part 3에서 만든 것처럼, 에러가 나면 담당자에게 슬랙이나 이메일로 알립니다. 알림에는 워크플로우 이름, 실패 시간, 에러 메시지를 넣습니다. 알림이 너무 자주 오면 무뎌지니, 일시적 오류는 재시도로 걸러내고 진짜 문제만 알리게 조정합니다.

백업은 두 가지를 합니다. 워크플로우 내보내기는 JSON 파일로 저장됩니다. 중요한 워크플로우는 변경할 때마다 내보내어 보관합니다. 셀프호스팅이라면 데이터 볼륨 전체를 백업합니다. n8n의 모든 데이터는 볼륨에 있으므로, 볼륨 백업이 곧 전체 백업입니다. 복구 테스트도 가끔 해 보세요. 백업은 복구될 때 의미가 있습니다.

버전 관리도 도움이 됩니다. 워크플로우 JSON을 Git 저장소에 넣으면 변경 이력이 남습니다. 누가 언제 무엇을 바꿨는지 추적되고, 문제가 생기면 이전 버전으로 되돌릴 수 있습니다. 팀으로 운영한다면 거의 필수입니다.

운영 체크리스트
- 중요 워크플로우에 Error Workflow 연결
- 실행 이력 주기적 확인
- 워크플로우 JSON 백업과 볼륨 백업
- n8n 버전 업데이트 계획

핵심 정리
- 실행 이력으로 상태를 보고, Error Workflow로 알림을 받는다.
- 백업은 워크플로우 JSON과 데이터 볼륨, 두 가지를 한다.
- Git에 넣어두면 변경 이력 추적과 롤백이 쉽다.
