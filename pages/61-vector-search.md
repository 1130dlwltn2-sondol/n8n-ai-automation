# 61. 벡터 스토어와 검색 고도화

기본 RAG가 동작하면, 다음은 검색 품질을 높이는 단계입니다. 실무에서 답이 틀리는 경우의 대부분은 모델이 아니라 검색의 문제입니다.

첫째, 하이브리드 검색입니다. 벡터 검색은 의미가 비슷한 문서를 잘 찾지만, 고유명사나 코드 같은 정확한 단어에는 약합니다. 키워드 검색과 벡터 검색을 함께 쓰고 결과를 합치면 둘의 장점을 살릴 수 있습니다. 제품명이나 인명처럼 정확한 일치가 중요한 문서에는 특히 효과적입니다.

둘째, 리랭킹입니다. 1차로 넓게 후보를 뽑고, 그중에서 질문과 가장 관련 있는 몇 개만 다시 골라 씁니다. 후보를 20개 뽑아 상위 5개만 쓰는 식입니다. 검색량은 늘지만 답의 정확도가 올라갑니다.

셋째, 메타데이터 필터입니다. 문서에 부서, 날짜, 문서 종류 같은 정보를 함께 저장해 두고, 검색할 때 조건을 겁니다. "2026년 영업팀 문서에서만 찾아" 같은 식입니다. 문서가 많아질수록 필터의 효과가 커집니다.

넷째, 청크 전략 조정입니다. 표가 많은 문서는 표 단위로, FAQ는 질문-답변 쌍으로 나누는 식으로 문서 성격에 맞춥니다. 나누는 단위가 검색 품질에 직접 영향을 줍니다.

이런 고도화는 한 번에 다 적용하지 않습니다. 기본 RAG를 만들고, 실제 질문 20개 정도로 테스트하면서 어디서 틀리는지 봅니다. 검색된 조각이 질문과 무관하면 검색을, 조각은 맞는데 답이 틀리면 프롬프트를 고칩니다. 문제를 좁혀서 고치는 것이 순서입니다.

핵심 정리
- 답이 틀리면 모델보다 검색을 먼저 의심한다.
- 하이브리드 검색, 리랭킹, 메타데이터 필터가 대표 고도화 기법이다.
- 실제 질문으로 테스트하며 문제 지점을 좁혀 고친다.
