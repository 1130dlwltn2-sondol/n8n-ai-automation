# Part 4. 스케줄과 웹훅

## 40. 스케줄 트리거

정해진 시간에 자동으로 실행되는 워크플로우에는 Schedule Trigger를 씁니다. 보고서 발송, 데이터 수집, 정기 알림 같은 반복 업무의 출발점입니다.

설정은 간단합니다. 매분, 매시간, 매일, 매주, 매월, 사용자 지정 중에서 고릅니다. 매일 아침 9시라면 Daily를 고르고 시간을 지정합니다. 복잡한 일정은 Custom의 cron 표현식으로 씁니다. 예를 들어 평일 아침 9시는 0 9 * * 1-5 입니다. cron 표현식이 낯설다면 생성기 사이트에서 만들어 복사해 오면 됩니다.

스케줄 워크플로우를 만들 때 주의할 점이 있습니다. 첫째, 워크플로우를 Active 상태로 켜야 실제로 시간에 맞춰 실행됩니다. 꺼져 있으면 스케줄이 와도 실행되지 않습니다. 둘째, 실행 시간이 겹치지 않게 합니다. 전날 작업이 안 끝났는데 다음 스케줄이 시작되면 중복 실행이 됩니다. 오래 걸리는 작업은 실행 간격을 넉넉히 잡거나, 중복 실행 방지 로직을 넣습니다. 셋째, 시간대를 확인합니다. 서버 시간대와 원하는 시간대가 다르면 엉뚱한 시간에 실행됩니다. n8n 설정의 시간대를 확인해 두세요.

정기 실행되는 워크플로우는 실행 이력이 쌓입니다. Executions 탭에서 성공과 실패를 확인할 수 있고, 실패한 건은 다시 실행할 수도 있습니다. 정기 보고서처럼 중요한 것은 Error Workflow 연결과 함께 운영하는 것이 좋습니다.

실습: 아침 브리핑
1. Schedule Trigger를 매일 아침 8시로 설정하기
2. HTTP Request로 날씨 API 호출하기
3. Set 노드로 메시지 다듬어 출력하기

핵심 정리
- Schedule Trigger는 정해진 시간에 워크플로우를 시작한다.
- 복잡한 일정은 cron 표현식으로 지정한다.
- Active를 켜야 실제 실행되고, 시간대를 확인한다.
