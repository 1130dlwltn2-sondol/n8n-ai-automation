# 32. 에러 처리

자동화는 사람이 안 보고 돌기 때문에, 에러 처리가 곧 신뢰성입니다. n8n은 노드 단위와 워크플로우 단위, 두 단계의 에러 처리를 제공합니다.

노드 설정의 Settings 탭에는 On Error 옵션이 있습니다. 기본값은 워크플로우를 멈추는 것이지만, Continue(Regular Output)로 바꾸면 에러가 나도 다음 노드로 진행됩니다. 에러가 난 아이템은 error 필드와 함께 전달되어 뒤에서 분기 처리할 수 있습니다. Continue(Error Output)도 비슷한데, 에러 출력을 별도 가지로 빼는 방식입니다. Retry On Fail을 켜면 실패한 요청을 지정 횟수만큼 다시 시도합니다. 일시적인 네트워크 오류에 유용합니다.

워크플로우 전체의 에러를 받고 싶다면 Error Trigger를 씁니다. 새 워크플로우에 Error Trigger 노드를 놓고, 원래 워크플로우의 설정에서 Error Workflow로 지정합니다. 원래 워크플로우에서 처리되지 않은 에러가 나면 이 에러 워크플로우가 실행됩니다. 보통은 에러 내용을 슬랙이나 이메일로 알리는 용도로 씁니다.

실무 팁을 몇 가지 정리합니다. 외부 API 호출 노드에는 Retry를 켜 두는 것이 기본입니다. 중요한 워크플로우에는 Error Workflow를 반드시 연결합니다. 에러 알림에는 에러가 난 워크플로우 이름, 시간, 에러 메시지를 포함시켜야 나중에 추적이 됩니다. 그리고 에러가 났을 때의 기본 동작을 문서로 남겨 두면, 팀원이 이어받기 쉽습니다.

실습: 에러 알림 워크플로우
1. Error Trigger로 시작하는 워크플로우 만들기
2. 에러 정보를 받아 슬랙으로 알리는 노드 연결하기
3. 테스트용 워크플로우의 Error Workflow로 지정하기

핵심 정리
- 노드 단위: Retry, Continue 옵션으로 개별 실패에 대응한다.
- 워크플로우 단위: Error Trigger로 전체 에러를 받아 알린다.
- 에러 알림에는 이름, 시간, 메시지를 포함시킨다.
