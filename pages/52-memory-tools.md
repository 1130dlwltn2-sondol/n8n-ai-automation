# 52. 메모리와 도구

에이전트가 대화를 이어가려면 메모리가 필요합니다. Memory 서브노드는 이전 대화 내용을 저장했다가 다음 호출 때 함께 넣어 줍니다. Window Buffer Memory는 최근 N개의 메시지를 기억합니다. 간단한 챗봇에는 이것으로 충분합니다.

도구는 에이전트의 손발입니다. n8n에서는 대부분의 노드를 도구로 바꿔 연결할 수 있습니다. 도구로 쓸 때는 노드 설정에서 도구 모드를 켜고, 이름과 설명을 적습니다. 설명이 곧 에이전트에게 주는 사용 설명서이므로 공들여 씁니다. 입력값의 형태도 명확히 정합니다. 예를 들어 "날짜는 YYYY-MM-DD 형식으로 입력" 같은 식입니다.

도구 설계의 실무 원칙을 정리합니다. 첫째, 하나의 도구는 하나의 일을 합니다. "검색하고 요약하고 보내기" 같은 만능 도구는 에이전트를 헷갈리게 합니다. 둘째, 위험한 도구는 분리합니다. 읽기 전용 도구와 쓰기 도구를 나누고, 쓰기 도구는 승인 절차 뒤에 둡니다. 셋째, 도구의 실패를 가정합니다. API가 에러를 내면 에이전트가 알아서 대처하도록, 에러 메시지를 이해하기 쉽게 돌려줍니다.

휴먼인더루프는 에이전트와 사람 사이의 승인 단계입니다. 에이전트가 중요한 결정을 내리기 전에 사람에게 확인을 요청합니다. n8n에서는 승인 대기 노드나, 슬랙 승인 버튼과 웹훅을 조합해 구현합니다. 예를 들어 "환불 처리 전 담당자 승인" 같은 흐름입니다. 자동화의 편리함과 통제의 균형을 맞추는 장치입니다.

실습: 메모리 있는 챗봇
1. AI 에이전트 노드에 Window Buffer Memory 연결
2. 같은 세션으로 두 번 질문해 맥락이 이어지는지 확인

핵심 정리
- 메모리는 대화 맥락을 유지하는 저장소다.
- 도구는 이름과 설명이 명확해야 에이전트가 잘 쓴다.
- 위험한 작업은 읽기와 쓰기를 분리하고 승인을 둔다.
